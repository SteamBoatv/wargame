## 术语表 ⭐

- **前线放置规则 v2**：建筑/空降/突袭只能放在「己方前线+余量」内。前线 = 己方存活的非守备队机动单位∪建筑的最大 s，取**8 秒滑窗最小值**（防单兵冲锋刷前线）。常量在 `js/data.js` 的 `FRONT`。
- **滑窗最小值**：`frontSmooth(side)` 取过去 8 秒内前线的最低值，而非瞬时值。防止 50 金侦察兵冲一下就解锁深处放置。
- **placeKind**：放置物三分法 `'bldg' | 'drop' | 'horde'`（`js/data.js` 的 `placeKind(P)`）。核心、客机预检、放置虚影、前线界标**必须全部用同一个谓词**，否则出现「房主能放、客机不能」。
- **资产化**：反应堆（`b_workshop`）可花钱升到 Lv2/Lv3（`WS_UP` 表，×1.7/×2.3 产量），被拆返还投资 55%、主动回收 65%（`WS_SALVAGE`）。
- **掠夺 / PLUNDER**：掠夺军阀的经济机制。越过半场线的己方机动单位按**深入深度**产金（软坡度，`ramp=0.11L` 处满额），总量计 `cap=5` 个封顶，`rate=3.0`。实现在 `js/game.js` 的 `plunderOf(side)`。
- **匪群突袭 / HORDE**：军阀技能，250 金投放 5 名会推进的常规部队（对照元帅空降是原地驻防、25 秒消散）。
- **单向税**：只有工程师承担、元帅免疫的隐性损失（拆建筑送赏金+经验、建筑不能占哨站/捡空投、陨石砸建筑、建筑无治疗）。本轮修复了其中四条：赏金减半+零经验+零军衔+零连斩、陨石对建筑免疫且移出落点质心。**未修**：建筑仍不能占哨站、不能捡空投（判定为合理设计）。
- **止血包**：六案评审里「单向税修复」方案的代号——不动任何收益数字，只废除上述单向税。定位是任何收益侧方案的前置补丁，单独用不够。
- **守备队 / 空降（AIRDROP）**：元帅技能投放的部队，`guard:true`——只在落点 `leash=120` 内活动、不推进战线、25 秒到期消散、`plunderOf` 与 `frontInstant` 都排除它。这三条自限是它能享受「哨站旗豁免」的理由，也是匪群突袭**不能**享受的理由。
- **老兵军衔 / VET_RANKS**：`js/data.js` 的两级军衔（⭐老兵 / 🔥精英），带 `scale/glow/aura/blur` 四个视觉参数。**这套分级管线已在实战验证可读**，第三时代英雄的视觉差异化可直接复用；但金 `#ffd76a`、橙 `#ff7a34` 两色已被它占用。
- **观战模式**：`?watch=` 独立链接，观众**直接渲染主机坐标系、不做镜像**（`mir=0`）。这是多人对战「废掉 180° 镜像」的现成先例。
- **死区**：反应堆理论产量最高的位置（靠近敌方）在实战中守不住——回本需 34 秒而实际寿命 9~18 秒，所以收益梯度的上半段数学上永远不该建。
- **净军费口径 vs 毛口径**：净军费 = 累计流入 − 经济投资（真正能买兵的钱）；毛口径不扣投资。**平衡结论必须用净口径**——毛口径会得出「差距 38%」的伪结论，净口径下 300 秒基线差距仅约 3%。
- **SOLO_LOCKED**：`js/data.js:4` 的单人远征封存开关（当前 `true`）。菜单单人区灰显、三处开局路径拦截。解封改 `false` 即可。
- **appId**：Trystero 房间号（`js/net.js` 的 `joinRoom`），当前 `kip-wargame-pvp-v2`。**改线材协议必须升它**，否则新旧客户端会进同一房间互相拖死。
- **TELE_VER**：遥测版本号（`js/telemetry.js`），当前 `2026.07.28-warlord`。跨版本数据隔离的唯一手段。
- **?v= 缓存串**：`index.html` 里 12 个 script + 1 个 css 的查询串，当前 `20260728a`。防「HTML 新、JS 旧」混版。
- **Yellow**：Tiny Swords 官方第五种队伍配色。项目当初导入脚本只写了 4 色，Yellow 整套 45 张躺在源包里从未解包——是骑士团第三时代的「白捡」素材。
- **REF**：候选对比图里橙色标号的那一格，指游戏里现有的 `blue_mecha_idle.png`，作为风格基准。
- **mech_v1..v6**：Codex 生成的六个机械军团英雄候选设计。**用户已选定 #4（远程攻城炮）与 #5（近战盾墙）**。
- **星形拓扑 / 辐条 / 枢纽 / 路牌**：3~4 人对战的架构方案。N 条辐条从各自基地汇聚到中央枢纽；「路牌」是每人一个的出兵方向开关（部队到枢纽且无敌军时按它转向）。
- **gap()**：星形拓扑下替代 `Math.abs(a.s-b.s)` 的距离函数（同辐条比距离／都在枢纽圈内绕圆心算／否则无穷大）。**尚未实现，只是设计**。

## 尝试过的方案(按时间顺序)

1. **经济差距用毛口径衡量** → 得出「元帅领先 38%」→ **被审查推翻**：那是「元帅无脑买满 9 级矿」的稻草人策略在毛口径下的产物，净军费口径下 300 秒基线仅差约 3%。**保留教训：平衡结论一律用净口径**。
2. **六案经济方案对抗评审**（6 设计 + 6 审查 + 1 批判，Opus）→ 记分：削元帅 8 分、资产化 7.5、单向税修复 6.5、高风险高回报 6、保守调参 4.5、身份差异化 4 → **采纳组合**：止血包 + 资产化，削元帅封存作长局保险丝。
3. **掠夺用硬阈值（越过 0.5L 即满额）** → 审查证实两头错：军阀速度 95 而对手最快 70，自然接战线恒在 0.57L 之后 → 一开打就无条件满额；军阀内战速度对称、接战点恰好落在 L/2、双方前排各停 ∓14px → **双方恒为 0、经济锁死** → **改为软坡度**（`ramp`），一次解决两头。
4. **匪群突袭复用空降的哨站旗豁免** → 被证实是后门：空降兵是 guard（不推进、25 秒消散、打不了城堡），突袭兵三条自限一条没有 → 被打爆的一方每 45 秒能把 4 个推进单位投到掠夺线前 134px → **改为突袭不吃豁免也不吃 0.45L 保底**。

## 关键决定

- **第三时代 = 限量英雄单位，而非更贵的常规兵**（用户拍板）。实现上也最省：现成的 `countBldg` **只按 `u.type` 计数、不要求是建筑**，对任意兵种直接可用；且只读 `G.units` → 客机能自算、主机能复验、**快照零改动**。而「每局限购 N 次」是累计量，必须新增快照字段。
- **掠夺军阀不出英雄**（用户拍板，理由：匪帮出不了英雄符合设定）。第三时代改为掠夺质变／全军狂暴／总攻号令三选一，**尚未选定**。
- **英雄候选选定 #4（远程攻城炮）+ #5（近战盾墙）**。我曾建议 #1，用户改选 #5——#5 的盾+冲击炮剪影更贴「近战」，判断比我准。
- **单人模式封存**：专注联机，平衡只对 PvP 负责。副作用是六案审查里所有 PvE 顾虑（元帅 PvE 降三成、AI 旧矿曲线补丁、per-mode 常量分层）全部降级为「解封时再处理」。
- **哥布林兵种可自由下调**：它们原本按「被玩家打的 AI 敌人」调的（火把狂徒近乎严格优于剑士），单人封存后改这三行零风险。
- **TURN 中继无法隐藏服务器 IP**：Cloudflare 免费版不代理 UDP，中继按原理要求客户端直连真实地址。仓库里没有地址（凭证运行时拉取），但玩家开 DevTools 能看到。已向用户说明并获接受。
- **遥测走 Cloudflare 橙云代理**（`wg.littleshark.xin`），源站真实 IP 不进开源仓库。
